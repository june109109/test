# 3-1. CPU·메모리·OS의 역할

[목차](../README.md) · [정답·해설](01-hardware-os-answers.md)

예상 40분. 목표: 코어·논리 CPU·주소 공간·스케줄러를 구분하고, 자원 숫자만으로 성능을 확정하지 않습니다.

## 1. 내 코드를 누가 실행하나

소스 코드는 실행 환경을 거쳐 기계가 수행할 작업이 됩니다. CPython에서는 일반적으로 소스를 bytecode로 컴파일하고 인터프리터가 실행합니다. Python이 C 확장 모듈을 호출하면 그 안의 기계어도 CPU에서 실행됩니다. ‘Python은 인터프리터 언어이니 컴파일 단계가 전혀 없다’는 설명은 부정확합니다.

CPU는 실행할 명령을 처리하고 메모리는 코드·데이터·실행 상태를 보관합니다. 운영체제는 프로세스의 주소 공간, 스레드의 실행 기회, 파일·네트워크 같은 자원 접근을 관리합니다. 앱은 보통 시스템 호출을 통해 커널에 작업을 요청합니다. 시스템 호출마다 반드시 다른 스레드로 전환되는 것은 아닙니다.

## 2. 자원 용어

| 용어 | 의미 | 혼동하면 생기는 문제 |
| --- | --- | --- |
| 물리 코어 | CPU 내부의 실행 자원 단위 | 코어 수만큼 모든 프로그램이 선형 가속된다고 기대 |
| 논리 CPU | OS 스케줄러가 보는 실행 대상 | SMT 논리 CPU를 독립적인 두 물리 코어와 동일시 |
| 가상 주소 공간 | 프로세스가 보는 주소 체계 | 예약된 주소 크기를 실제 RAM 사용량과 동일시 |
| 물리 메모리·RSS | 실제 RAM, 프로세스에 상주하는 페이지 규모의 지표 | 공유 페이지 때문에 RSS 합계가 고유 사용량과 다를 수 있음 |
| CPU quota | 일정 기간 사용할 수 있는 CPU 시간 예산 | 보이는 코어 수와 실제 사용할 용량을 혼동 |

SMT는 한 물리 코어의 실행 자원을 여러 논리 CPU가 공유하는 방식입니다. 부하 종류에 따라 이익이 다르므로 ‘논리 CPU 두 개=성능 두 배’가 아닙니다. 메모리 계층의 캐시·RAM·저장장치는 접근 비용도 다릅니다.

## 3. 실행과 대기

스레드가 실행 준비 상태여도 CPU가 당장 배정되지 않을 수 있습니다. 실행 가능한 스레드들 중 누가 언제 실행할지 스케줄러가 정합니다. I/O를 기다리느라 잠든 스레드는 보통 계속 CPU를 사용하며 기다리지 않습니다. 반대로 조건을 반복 검사하는 busy loop는 기다리는 동안 CPU를 소비할 수 있습니다.

페이지 폴트가 발생하면 메모리 접근을 처리하기 위한 커널 작업이 필요하며 경우에 따라 저장장치 접근까지 갈 수 있습니다. RSS가 커졌다고 무조건 누수는 아니고 캐시·정상 데이터 증가도 원인입니다. 메모리 한도를 넘으면 프로세스가 종료될 수 있으므로 속도만 보지 않습니다.

## 4. 설계 비교

| 선택 | 기대 이익 | 비용·한계 |
| --- | --- | --- |
| 더 빠른 코어 | 순차 CPU 경로 가속 | 비용, I/O·락 대기에 효과 제한 |
| 코어 수 증가 | 병렬 가능한 계산량 증가 | 병렬화·동기화·직렬 구간 한계 |
| 메모리 증가 | 큰 작업·캐시·스와핑 감소 | 비용, 앱이 활용 못 하면 효과 제한 |
| 프로세스 증가 | 격리·병렬 CPU 사용 가능 | 각 프로세스 메모리·연결·초기화 비용 |

**판단 순서:** 느린 시간을 CPU 실행·CPU 대기·I/O·락 대기 등으로 나눕니다. 실제 자원 제한을 확인한 뒤 증설·알고리즘 개선·I/O 개선 중 무엇이 효과적인지 가설을 세웁니다. ‘CPU 사용률 100%’는 도구가 한 논리 CPU 기준인지 전체 할당량 기준인지 확인해야 합니다.

## 관찰 과제

다음 명령은 값만 읽으며 설정을 바꾸지 않습니다.

```bash
python3 -c 'import os, platform; print(platform.python_implementation(), platform.python_version()); print("visible CPUs:", os.cpu_count())'
```

Linux cgroup v2 환경이라면 `/sys/fs/cgroup/cpu.max`가 quota와 period를 보여줄 수 있습니다. `400000 100000`은 기간당 CPU 시간 비율로 약 4 CPU의 예산을 뜻하며, 전용 물리 코어 네 개를 보장한다는 뜻은 아닙니다. 파일이 없거나 `max`이면 다른 제한과 환경을 확인합니다.

이 환경에서는 2026-10-01 CPython 3.12.14, 보이는 CPU 5개, affinity 5개, 해당 cgroup 비율 4를 관찰했습니다. 다른 작업·상위 제한도 성능에 영향을 줄 수 있습니다. 이후 측정의 조건이지 모든 사용자 환경의 값이 아닙니다.
