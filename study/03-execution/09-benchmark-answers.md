# 3-9. 정답과 해설

[본문](09-benchmark.md)

## Q1 — 입증되지 않았다, 1점

코드에서 CPU 작업은 await 없이 루프 스레드에서 실행됩니다. 짧은 실험의 값 차이만으로 병렬성을 결론 낼 수 없습니다. 복습: 5절.

## Q2 — 부를 수 없다, 1점

워커 시작 외에 0.1초 대기 워밍업과 작업 제출·결과 수집이 포함되어 있습니다. 측정 경계를 정확히 표시해야 합니다. 복습: 4절.

## Q3 — 약 0.1초 + 부가 비용, 2점

ceil(8/4)×0.05=0.1초에 1점. 연결·스케줄링·서버 스레드·데이터 전송·IPC 등 추가 비용 두 개에 1점입니다. 비슷한 숫자가 나왔다고 완전한 동시 시작이나 제로 오버헤드를 뜻하지 않습니다. 복습: 2·5절.

## Q4 — 유효 업무량이 다르다, 2점

성공 6개와 8개를 동등하게 비교할 수 없다는 설명 1점. 오류를 따로 보고하고 원인을 해결한 뒤 동일한 작업·결과 검증으로 다시 측정하거나 성공률과 처리량을 함께 비교하는 방법에 1점. 복습: 6절.

## Q5 — 실험 범위를 넘는 일반화, 4점

여기서는 순수 Python 계산과 짧은 loopback 대기를 비교했습니다. 실제 API가 동기 SDK·DB·큰 직렬화·네이티브 연산 중 어디에 제한되는지 확인해야 합니다. 준비된 풀의 작업 시간과 전체 배포·시작 시간을 구분합니다. 프로세스별 메모리·클라이언트·연결·입력 복사·취소·오류 처리를 포함합니다. 실제 부하·같은 응답·오류율·꼬리 지연·자원 사용으로 소규모 적용을 검증합니다.

채점: 실제 작업 분류 1점, 측정 경계 1점, 운영 비용 1점, 동일 조건·결과·여러 지표 검증 1점. 복습: 4~6절.

## 3장 종합 확인

`async`, 스레드, 프로세스라는 이름 대신 ‘어느 실행 주체가 무엇을 기다리고 어느 자원을 점유하는가’를 설명할 수 있으면 4장의 FastAPI 실습을 해석할 준비가 됐습니다. 같은 코드도 버전·빌드·CPU 예산·작업 크기에 따라 선택이 달라질 수 있다는 점을 유지하세요.
