# 3-1. 정답과 해설

[본문](01-hardware-os.md)

## Q1 — 아니다, 1점

SMT로 한 물리 코어가 여러 논리 CPU를 제공할 수 있고 가상화 환경의 표기도 있습니다. 물리 자원 공유·quota를 함께 확인해야 합니다. 복습: 2절.

## Q2 — 아니다, 1점

블로킹 I/O로 잠든 스레드는 보통 CPU를 양보합니다. busy polling은 별개의 방식으로 CPU를 사용할 수 있습니다. 복습: 3절.

## Q3 — 가상 예약과 상주 메모리는 다름, 2점

가상 주소가 모두 물리 RAM에 상주하는 것은 아니라는 설명 1점. RSS·공유 페이지·메모리 한도·스왑·페이지 폴트 등 실제 사용 조건 확인 1점. RSS들을 단순 합산해 고유 사용량으로 단정하지 않습니다. 복습: 2~3절.

## Q4 — 보장되지 않는다, 2점

quota 비율은 약 2 CPU 시간 예산이라는 계산 1점. 16개 프로세스가 예산을 공유하고 경쟁·전환 비용을 낼 수 있다는 설명 1점. CPU 숫자만으로 풀 크기를 고정하지 않습니다. 복습: 관찰 과제.

## Q5 — 병목과 제한을 확인, 4점

실제 CPU quota·affinity·메모리 한도와 부하 조건을 확인합니다. CPU 실행, 스케줄러 대기, I/O·락 대기, 메모리 압박을 나눕니다. 순차 계산이면 알고리즘·코어 성능, I/O이면 요청 수·외부 지연, 메모리이면 데이터·캐시 정책을 비교합니다. 같은 조건으로 개선 효과와 오류·비용을 확인합니다.

채점: 실제 제한 1점, 대기 원인 구분 1점, 원인에 맞는 대안 1점, 비교 검증 1점. 복습: 3~4절.
