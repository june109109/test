# 3-6. 정답과 해설

[본문](06-strategies.md)

## Q1 — 함께 사용 가능, 1점

여러 프로세스에 루프를 하나씩 두고 동기 SDK를 스레드풀에 맡기는 구성이 가능합니다. 단, 자원 한도도 함께 계산해야 합니다. 복습: 1·4절.

## Q2 — 아니다, 1점

semaphore는 동시 진입 수를 제한하지만 대기하는 task 객체·참조·입력은 이미 존재합니다. 생산·소비 구조로 생성량도 제어할 수 있습니다. 복습: 2절.

## Q3 — 작은 일의 전달 비용, 2점

직렬화·큐·IPC·스케줄링 비용이 계산보다 클 수 있다는 설명 1점. 배치로 묶기·데이터 위치 변경·단순 순차 처리 등의 비교 대안 1점입니다. 배치가 커지면 지연·부하 불균형 비용도 확인합니다. 복습: 1·3절.

## Q4 — 모두 진행할 수 없다, 2점

DB 연결을 점유해야 하는 작업은 최대 해당 연결 예산의 제약을 받는다는 설명 1점. 풀 획득 대기·상위 큐·수용 제한 같은 위치와 정책 설명 1점. 단일 요청이 연결을 쓰는 기간과 다른 구간도 구분해야 합니다. 복습: 4절.

## Q5 — 전체 자원 지도, 4점

예시: 동기 SDK는 안전성을 확인한 제한된 스레드풀에 맡기고 DB는 별도 연결 예산을 둔다. 입력 큐와 획득 대기를 제한하며 하류 용량을 넘기지 않는다. 상위 요청 취소 뒤 계속 실행될 SDK 작업과 DB 취소·정리 동작을 구분한다. 루프 지연·스레드 사용·DB 획득 대기·오류·응답 시간을 관찰한다.

채점: 실행 경계 1점, 풀·큐·하류 한도 1점, 취소·정리 1점, 병목 지표 1점. 특정 구조 이름만 나열하는 답보다 누가 어디서 기다리는지 설명하는 답이 좋습니다.
