# 3-6. 기다림을 활용하는 세 가지 방법

[목차](../README.md) · [이전](05-sync-async.md) · [정답·해설](06-strategies-answers.md)

예상 45분. 목표: 프로세스·스레드·이벤트루프를 코드 모양이 아니라 작업·자원·운영 조건으로 선택합니다.

## 1. 대기를 겹치는 공통 목적

각 작업이 외부 응답을 기다릴 때 다른 작업을 진행하면 총 완료 시간을 줄일 수 있습니다. 세 방식은 실행과 상태를 관리하는 단위가 다릅니다. 실제 서비스에서는 프로세스 여러 개 안에 각각 이벤트루프와 스레드풀이 함께 있을 수 있습니다. 셋 중 하나만 쓰는 순수한 구조가 필수는 아닙니다.

| 기준 | 프로세스 | 스레드 | 이벤트루프·코루틴 |
| --- | --- | --- | --- |
| 기본 단위 | 분리된 주소 공간과 실행 | 같은 프로세스 안의 OS 실행 흐름 | 루프가 관리하는 협력적 작업 |
| I/O 대기 겹침 | 가능 | 가능 | 비동기 API와 양보를 통해 가능 |
| 순수 Python CPU 병렬성 | 여러 CPU 예산에서 가능 | GIL 있는 CPython은 제한 | 같은 루프의 CPU 계산은 병렬 아님 |
| 데이터 공유 | IPC·직렬화 등 | 쉬운 공유, 락·불변성 관리 | 공유 가능, await 전후 경쟁 관리 |
| 주요 비용 | 메모리·시작·전달·프로세스별 풀 | 스택·전환·락·스레드 한도 | 비동기 라이브러리·취소·블로킹 혼입 |
| 잘 맞는 출발점 | 독립 계산·격리 | 기존 동기 I/O 라이브러리 | 많은 대기와 비동기 생태계 |

이벤트루프가 자동으로 가장 적은 메모리를 쓴다고 보장할 수는 없습니다. task마다 큰 본문을 보관하면 메모리가 커지고, 같은 자원을 실제로 얼마나 유지하는지가 중요합니다.

## 2. ‘작업 수’와 ‘진행 중 수’ 구분

할 일이 10만 개 있다고 10만 개를 동시에 시작할 필요는 없습니다. 입력을 순차적으로 공급하는 큐와 유한한 실행 자원을 이용합니다. semaphore는 동시에 임계 영역에 들어가는 수를 제한하지만 이미 만든 task 10만 개의 메모리를 없애지는 않습니다. task 자체의 수를 제한하려면 생산·소비 구조나 배치가 필요할 수 있습니다.

**backpressure**는 소비자가 감당하지 못할 때 생산 속도를 늦추거나 수용을 제한하는 방식입니다. 단순히 대기열을 무한히 키우는 것과 다릅니다. 큐가 가득 찼을 때 대기·거절·낮은 우선순위 작업 포기 중 어떤 정책인지 정합니다.

## 3. 선택 절차

1. 시간이 CPU 실행인지 I/O·락·풀 대기인지 확인합니다.
2. 라이브러리가 동기인지 실제 비동기인지, GIL을 해제하는 계산인지 확인합니다.
3. 데이터 전달 크기·상태 공유·실패 격리 요구를 적습니다.
4. CPU·메모리·소켓·DB·외부 API 한도 중 작은 제약을 확인합니다.
5. 완료·오류·취소·종료 시 미완료 작업의 처리를 설계합니다.
6. 같은 작업과 입력으로 결과·지연·처리량·자원을 비교합니다.

예를 들어 작은 파일 메타데이터를 동기 SDK로 조회하고 최대 병행 수가 10이면 스레드풀이 간단할 수 있습니다. 수천 연결의 대기를 처리하고 라이브러리가 지원한다면 asyncio가 유리할 수 있습니다. 큰 CPU 계산은 프로세스·적절한 네이티브 계산 라이브러리를 비교하되 데이터를 옮기는 비용을 봅니다.

## 4. 결합할 때 생기는 자원 곱셈

인스턴스 2×워커 4×스레드 20이면 동기 작업 실행 슬롯이 이론상 160개일 수 있습니다. 각 작업이 DB 연결을 요구하는데 전체 사용 가능 연결이 40이면 모두 DB 작업을 동시에 진행할 수는 없습니다. HTTP/2 연결 수와 스트림 수, 스레드 토큰과 asyncio executor 수도 함부로 동일시하지 않습니다.

풀을 줄이면 지연을 없애는 대신 대기를 더 앞에서 제어할 수 있습니다. 어디에서 대기하는지 관측하고 timeout과 부하 거절을 맞추는 것이 중요합니다. 이 자원 지도를 4장의 FastAPI에 적용합니다.

## 적용 과제

독립 이미지 계산, 동기 AWS SDK 조회, 수천 개의 느린 네트워크 읽기를 각각 설계하세요. 프로세스·스레드·루프 중 선택하고 동시성 한도와 데이터 전달·공유·취소 비용을 적습니다. 정확한 라이브러리를 모르면 확인해야 할 조건을 가정으로 표시합니다.
