# 3-8. 정답과 해설

[본문](08-gil.md)

## Q1 — 아니다, 1점

많은 블로킹 I/O 경로는 대기 중 GIL을 해제하므로 다른 스레드가 진행할 수 있습니다. GIL이 있다고 스레드의 I/O 병행이 무의미한 것은 아닙니다. 복습: 2절.

## Q2 — 아니다, 1점

선택한 빌드와 실제 런타임 설정·확장 모듈에 따라 다릅니다. 버전·빌드 지원·현재 상태를 구분해야 합니다. 복습: 3절.

## Q3 — GIL과 이벤트루프는 다른 경계, 2점

GIL 해제는 다른 OS 스레드의 Python 실행을 허용할 수 있다는 설명 1점. 호출한 이벤트루프 스레드는 여전히 동기 SDK의 반환을 기다려 같은 루프의 다른 task를 진행하지 못할 수 있다는 설명 1점. to_thread 등으로 실행 위치를 바꾸거나 비동기 SDK가 필요할 수 있습니다. 복습: 2절.

## Q4 — 전달·시작·수명·제한, 2점

직렬화 가능한 함수·데이터, spawn/forkserver/fork의 차이, main guard, 입력·출력 복사 크기, 프로세스별 메모리·연결, 자원 초기화, CPU quota 등 두 조건을 설명하면 각 1점입니다. 복습: 4절.

## Q5 — 조건부 진단과 대안, 4점

GIL 있는 CPython의 순수 Python 계산이라면 스레드가 여러 코어에서 같은 방식으로 병렬 계산하지 못할 수 있습니다. 프로세스 분할 또는 알고리즘·GIL을 해제하는 네이티브 구현 등을 비교합니다. free-threaded도 후보지만 패키지 지원·런타임 상태·동기화·메모리 비용을 검증해야 합니다. 입력 크기·CPU quota·워커 수·시작/전달 비용을 기록하고 결과가 같은지 확인합니다.

채점: GIL 조건을 명시한 가설 1점, 대안 두 개 1점, 환경·전달·시작 비용 1점, 결과·호환성 검증 1점. 복습: 2~5절.
