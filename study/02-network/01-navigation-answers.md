# 2-1. 정답과 해설

[본문](01-navigation.md)

## Q1 — 아니다, 1점

리다이렉트, HTML이 참조하는 이미지·CSS·스크립트, 이후 API 호출 등이 추가 요청을 만들 수 있습니다. 반대로 응답 캐시가 요청을 대신할 수도 있습니다. 복습: 1~2절.

## Q2 — 아니다, 1점

HTTP/3는 UDP 위의 QUIC를 사용하고 TLS 1.3을 통합합니다. QUIC에도 연결 설정은 있으므로 ‘TCP가 없다=연결 설정이 없다’도 틀립니다. 복습: 2절.

## Q3 — 캐시·연결·계측, 2점

예: DNS 캐시 적중, 기존 연결 재사용, 로컬 응답 캐시, 브라우저의 timing 표시·계측 제한. 타당한 설명 두 가지에 각 1점. DNS·TLS는 서로 다른 재사용이므로 한쪽만으로 양쪽 부재를 모두 설명하지 마세요. 복습: 3절.

## Q4 — 메인 스레드와 추가 자원, 2점

긴 JavaScript 작업·레이아웃/페인트 비용을 확인하면 1점, 추가 스크립트·API·폰트 의존성 등 초기 문서 이후의 경로를 확인하면 1점입니다. 요청 하나의 완료와 화면의 사용 가능 시점은 다릅니다. 복습: 4~5절.

## Q5 — 원인 분리, 4점

후보: 원거리 DNS·연결 왕복, 큰 정적 파일의 첫 다운로드, CDN/서버 캐시 미스. timing과 protocol·연결 재사용 정보, 파일 크기·캐시 적중 표시, 서버 측 요청·캐시 지표로 구분합니다. 재방문이 빨라졌다고 이 중 하나를 단정하지 않습니다. 해외 기기의 CPU 성능과 접속망도 혼동 요인일 수 있습니다.

채점: 타당한 후보 세 개 1점, 원인에 대응하는 관찰 방법 2점, 재사용·계측·클라이언트 등 단정의 한계 1점. 복습: 3~5절. CDN을 추천하기 전에 실제 지연이 어느 경로에서 생기는지 확인해야 합니다.
