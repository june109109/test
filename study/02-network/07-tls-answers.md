# 2-7. 정답과 해설

[본문](07-tls.md)

## Q1 — 아니다, 1점

검증한 호스트와 안전한 전송을 확보하는 것과 콘텐츠·사업의 진실성은 별개입니다. 악성 사이트도 유효한 인증서를 가질 수 있습니다. 복습: 1절.

## Q2 — 아니다, 1점

일반적인 전체 핸드셰이크에서 인증·키 교환으로 공유 키 재료를 만들고, 실제 데이터는 대칭키 기반 방식으로 보호합니다. 세션 재개·PSK 등의 다른 경로도 있습니다. 복습: 2절.

## Q3 — 전 구간은 아니다, 2점

TLS가 LB에서 종료되어 LB가 HTTP 내용을 읽는다는 점에 1점, LB~앱 HTTP 구간에는 해당 TLS 보호가 없다는 설명에 1점입니다. 재암호화를 해도 LB는 신뢰 종단으로 남습니다. 복습: 3절.

## Q4 — 협상 지연 절약과 재전송 위험, 2점

허용된 재개 상황에서 요청을 일찍 보낼 수 있다는 이익에 1점. 재전송 공격·중복 부작용 때문에 해당 요청을 early data에서 제외하거나 충분한 방어·멱등성 계약이 필요하다는 설명에 1점. 모든 초기 접속에 가능한 것은 아닙니다. 복습: 4절.

## Q5 — 검증 경로 복원, 4점

접속하려는 호스트와 실제 TLS 종료 지점을 확인합니다. 인증서 이름·기간·체인·시스템 시간을 점검하고, 환경의 승인된 CA 신뢰 설정을 확인합니다. 잘못된 인증서 배포나 체인 누락을 수정하고 필요한 신뢰 저장소를 정상 경로로 구성합니다. 검증이 켜진 상태에서 올바른 호스트 접속이 성공하는지 확인하며, 잘못된 이름·신뢰되지 않는 인증서가 거부되는지도 통제된 테스트에서 확인할 수 있습니다.

채점: 원인 후보를 계층별로 제시 1점, 검증을 끄지 않는 수정 1점, 프록시·종료 경계 반영 1점, 수정 후 실제 검증 1점. 복습: 3·5절.
