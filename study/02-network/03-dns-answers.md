# 2-3. 정답과 해설

[본문](03-dns.md)

## Q1 — 다르다, 1점

registrar는 등록·갱신 등 고객의 도메인 관리 절차를 제공합니다. 재귀 리졸버는 이름을 대신 조회하고 응답을 캐시합니다. 두 역할을 구분하면 1점. 한 업체가 여러 역할을 제공할 수 있어도 같은 기능은 아닙니다. 복습: 1절.

## Q2 — 불가능, 1점

A 레코드의 데이터는 IPv4 주소입니다. HTTPS·경로 라우팅·redirect는 다른 계층의 설정입니다. CNAME도 URL 경로를 지정하는 기능이 아닙니다. 복습: 4절.

## Q3 — 반드시 만료하지 않는다, 2점

기존 응답의 TTL이 이미 캐시에 적용돼 있다는 설명에 1점. 단순 모델에서 13:00까지 기존 값이 남을 수 있다는 계산에 1점. 권한 TTL 변경이 이미 내려간 캐시를 소급 수정하지 않습니다. 실제 정책 예외 때문에 정확한 전 세계 동시 전환 시각은 보장할 수 없습니다. 복습: 5절.

## Q4 — 조회 경로·연결 재사용 등, 2점

각 타당한 원인에 1점: 브라우저와 진단 도구의 리졸버/캐시 차이, 브라우저의 기존 연결 재사용, 프록시가 다른 곳에서 이름 해석, CDN·앱 캐시로 인한 응답 오인. 주소가 새 값인지와 응답 내용이 새 배포인지도 별개입니다. 복습: 3·5·6절.

## Q5 — DNS 전환은 시간과 서비스 준비가 필요, 4점

기존 TTL을 고려해 사전 조정하고, 새 서버의 호스트 처리·TLS·앱 상태를 준비합니다. 권한 응답과 대표 리졸버 응답을 확인하고 실제 HTTPS 동작을 따로 검증합니다. 구 서버에는 캐시·기존 연결로 트래픽이 남을 수 있으므로 바로 종료하지 않습니다. 문제가 생기면 DNS 복원만 믿지 말고 두 진입점의 상태와 사용자 영향·캐시 수명을 확인하며 복구합니다.

채점: 사전 TTL 이해 1점, 새 서버·인증서 준비 1점, 구 서버·기존 연결 고려 1점, DNS/앱 검증과 비즉시 복구 이해 1점. 복습: 2·5·6절.
