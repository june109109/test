# 7-4. 취소 전파와 끝나지 않은 스레드 — 정답·해설

[본문](04-cancellation.md) · [목차](../README.md)

## Q1 — 1점

아닙니다. 실행 중 스레드가 계속 동작할 수 있으며 실습에서 확인했습니다.

## Q2 — 1점

아닙니다. 이벤트루프가 callback과 취소를 처리할 실행 기회를 얻어야 합니다.

## Q3 — 2점

상위 호출자가 기대하는 취소 전파를 막습니다(1점). timeout/TaskGroup 정리와 수명 관리가 틀어지므로 정리 후 다시 전달하는 방식이 일반적입니다(1점).

## Q4 — 2점

논리적 입장 토큰만 반환되고 실제 스레드는 남아 있을 수 있습니다(1점). 새 요청과 기존 작업이 겹치므로 실제 작업 수명에 맞는 제한/관측이 필요합니다(1점).

## Q5 — 4점

각 1점: 요청 종료와 업로드 성공 여부 분리, SDK 자체 timeout/협력 취소, 실제 실행 작업·큐 한도와 정리, 작업 ID/멱등성/상태 조회. 강제 스레드 종료가 가능하다고 가정하면 안 됩니다.

8점 미만이면 틀린 질문과 관련된 본문을 복습하고, 조건을 하나 바꿨을 때 답이 달라지는 이유를 적으세요. 서술형은 제품 이름보다 제약·근거·비용·검증 방법을 평가합니다.
