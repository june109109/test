# 5-8. DB 커넥션 풀 예산 — 정답·해설

[본문](08-pool-budget.md) · [목차](../README.md)

## Q1 — 1점

SQLAlchemy QueuePool에서는 아닙니다. 수요에 따라 연결을 만들며 idle 최대 보관과 전체 동시 획득 한도를 구분합니다.

## Q2 — 1점

아닙니다. 풀 획득 대기 제한입니다. SQL 제한·요청 deadline은 별도로 구성합니다.

## Q3 — 2점

2×4×(6+2)=64입니다. 식 1점, 값 1점. 앱 외 연결과 배포 공존은 별도입니다.

## Q4 — 2점

10/0.1=100 transaction/s 근사(1점). 안정된 평균·계속 활용 가능하다는 가정이며 DB 포화/락/꼬리로 보장할 수 없음(1점).

## Q5 — 4점

앱 예산180, 최대5인스턴스×3워커이므로 워커당12(1점). 예: pool10+overflow2 또는12+0(1점). 배포/오토스케일 최대 상태에서 검사(1점), 대기·점유·DB병목 지표와 획득 timeout/backpressure(1점). 최대치까지 쓰지 않는 추가 여유도 합리적입니다.

8점 미만이면 틀린 질문과 관련된 본문을 복습하고, 조건을 하나 바꿨을 때 답이 달라지는 이유를 적으세요. 서술형은 제품 이름보다 제약·근거·비용·검증 방법을 평가합니다.
