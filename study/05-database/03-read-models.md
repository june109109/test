# 5-3. 역정규화와 읽기 모델

[목차](../README.md) · [정답·해설](03-read-models-answers.md)

예상 45분. 목표: 중복과 과거 사실을 구분하고, 읽기 최적화에 필요한 갱신·복구 비용을 설계합니다.

## 1. 화면마다 비싼 조인을 반복한다면

주문 목록에 고객 표시명, 품목 수, 총액이 필요합니다. 매번 원본 테이블을 조인·집계하는 비용이 실제로 커졌다면 `order_summary`를 만들 수 있습니다. 먼저 인덱스·불필요한 조회·N+1·페이지네이션을 고치는 것보다 읽기 모델이 정말 필요한지 비교합니다.

역정규화는 더 적은 계산·조인으로 읽기 위해 중복이나 사전 계산을 도입하는 선택입니다. 중복을 저장하는 순간 ‘어떤 사실이 원본이고 어떻게 따라잡는가’라는 책임이 생깁니다.

## 2. 비슷한 대안의 차이

| 대안 | 읽기 이익 | 지불하는 비용 | 맞는 조건 |
| --- | --- | --- | --- |
| 정규 원본+조인 | 최신 원본에 직접 질의 | 실행 시 조인·집계 | 부하가 감당 가능, 최신성 중요 |
| 일반 뷰 | 질의·권한 인터페이스 단순화 | 보통 결과 자체를 저장하지 않음 | SQL 중복을 줄임 |
| materialized view | 계산 결과 보관 | refresh 비용·신선도 | 주기적 보고서 |
| 같은 DB의 요약 테이블 | 읽기 경로 단축 | 모든 쓰기에서 갱신 규칙 유지 | 강한 일관성과 제한된 모델 |
| 비동기 읽기 모델/검색 색인 | 별도 확장·특화 검색 | 지연·중복 이벤트·재처리 | 지연을 허용하는 검색/조회 |
| 캐시 | 반복 결과 재사용 | 만료·무효화·cache miss | 원본에서 재생성 가능한 값 |

뷰를 만들었다고 질의 결과가 자동으로 캐시되지는 않습니다. materialized view의 갱신 방식과 동시에 읽을 수 있는 조건은 DB 구현별로 확인합니다.

## 3. 실패를 먼저 그리기

주문 DB commit은 성공했는데 검색 색인 갱신이 실패하면 두 시스템의 상태가 달라집니다. 하나의 DB transaction으로 HTTP 검색 요청까지 rollback할 수 없습니다. 별도 읽기 모델에는 재시도와 누락 탐지·재구축이 필요합니다.

transactional outbox는 원본 변경과 ‘전달할 이벤트’ 기록을 같은 DB transaction에 넣고 나중에 발행합니다. 전달 성공 후 확인 기록 전에 죽으면 중복 발행할 수 있으므로 소비자는 event_id 중복 제거와 버전 비교를 고려해야 합니다. outbox만으로 전 구간 exactly-once를 얻는다고 말하지 않습니다.

```text
원본 변경 + outbox 기록 (하나의 DB commit)
  → 발행기 → 이벤트 전달 → 읽기 모델 반영
                         ↘ 중복·역순·지연 처리
```

예를 들어 주문 버전 8이 먼저 도착한 뒤 버전 7이 도착했다면 최신 스냅샷 덮어쓰기 모델은 7을 거부할 수 있습니다. 하지만 이벤트가 ‘+1’ 같은 증분이라면 단순히 옛 번호를 버리는 전략으로 누락을 해결할 수 없습니다. 메시지 의미와 순서를 함께 설계해야 합니다.

## 4. 논증 연습

다음은 실제 토론 인용이 아닌 학습용 논증입니다.

**‘동일 transaction에서 요약도 고치자’**는 읽자마자 최신 값을 원하는 주문 상세에서 설득력이 있습니다. 반박은 쓰기 지연과 락 범위가 늘어난다는 것입니다. 재반박은 제한된 작은 요약만 원자적으로 갱신하고 비싼 검색 모델은 분리하는 절충입니다.

**‘비동기로 읽기 모델을 만들자’**는 읽기 확장과 장애 분리에 유리합니다. 반박은 주문 직후 목록에 안 보여 사용자 혼란이 생긴다는 것입니다. 재반박은 갱신 지연 SLO를 정하고, 주문 직후 원본 응답/임시 표시/read-your-writes 경로를 제공하는 것입니다. 모든 경우에 그 복잡도를 감수할 가치는 없습니다.

## 5. 적용 과제

‘검색은 5초 지연 허용, 결제 상태 화면은 최신이어야 함’이라는 조건에서 경로를 그리세요. 원본·색인 버전·최대 지연 경보·재구축 중 전환·오래된 이벤트 처리·실패 재시도 한도를 포함합니다.
