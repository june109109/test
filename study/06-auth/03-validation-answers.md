# 6-3. 콜백과 토큰 검증 — 정답·해설

[본문](03-validation.md) · [목차](../README.md)

## Q1 — 1점

다릅니다. decode는 내용 읽기이며 서명·issuer·audience·시간·시도 연결 검증이 필요합니다.

## Q2 — 1점

거부합니다. 정상 발급 토큰이어도 우리 client를 대상으로 한 인증 결과가 아닙니다.

## Q3 — 2점

state는 시작한 브라우저 로그인 시도와 callback(1점), nonce는 그 시도와 ID token(1점)을 연결합니다.

## Q4 — 2점

공격자 입력으로 외부 요청 폭증/지연을 만들 수 있습니다(1점). 신뢰한 키 출처에 제한된 갱신·캐시·rate limit과 실패 처리가 필요합니다(1점).

## Q5 — 4점

각 1점: state·브라우저·만료·일회 소비, PKCE와 고정 endpoint 교환, 서명/issuer/audience/exp/nonce 등, 실패 시 세션 미발급과 비밀 없는 로그. 라이브러리의 다중 aud/azp·키 회전까지 범위를 확인하면 좋은 보완입니다.

8점 미만이면 틀린 질문과 관련된 본문을 복습하고, 조건을 하나 바꿨을 때 답이 달라지는 이유를 적으세요. 서술형은 제품 이름보다 제약·근거·비용·검증 방법을 평가합니다.
