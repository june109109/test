# 6-4. 자체 로그인 상태: 서버 세션과 JWT — 정답·해설

[본문](04-sessions.md) · [목차](../README.md)

## Q1 — 1점

아닙니다. JWT는 형식, 쿠키는 저장·전송 수단이며 JWT를 쿠키에 담을 수도 있습니다.

## Q2 — 1점

아닙니다. 직접 읽기는 제한하지만 XSS가 사용자의 브라우저에서 인증 요청을 실행할 수 있습니다.

## Q3 — 2점

서버 세션은 중앙 상태 삭제/무효화가 쉽지만 매번 조회 비용이 있습니다(1점). JWT는 로컬 검증 가능하지만 만료 전 철회에 별도 상태·조회·짧은 수명 등이 필요합니다(1점).

## Q4 — 2점

브라우저가 쿠키를 자동 전송할 수 있기 때문(1점), CSRF token·적절한 SameSite·Origin 검증 등 구조에 맞는 대책 설명(1점). CORS 하나로 모든 CSRF가 방지된다고 하지 않습니다.

## Q5 — 4점

각 1점: 요구에 맞는 세션 선택, idle/absolute lifetime과 로그인 ID 회전, 즉시 철회/권한 변경 경로, Secure/HttpOnly/SameSite와 XSS·CSRF 대책. 제품 이름보다 비용 설명을 평가합니다.

8점 미만이면 틀린 질문과 관련된 본문을 복습하고, 조건을 하나 바꿨을 때 답이 달라지는 이유를 적으세요. 서술형은 제품 이름보다 제약·근거·비용·검증 방법을 평가합니다.
