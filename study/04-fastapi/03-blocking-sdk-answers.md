# 4-3. 정답과 해설

[본문](03-blocking-sdk.md)

## Q1 — 불가능, 1점

동기 함수는 호출 시 먼저 실행되고 일반 반환값을 await할 수 없습니다. 적절히 스레드로 옮기거나 실제 비동기 SDK를 사용해야 합니다. 복습: 1절.

## Q2 — 그렇다, 1점

get_object의 응답 본문은 스트리밍 객체입니다. read가 추가 네트워크 데이터를 기다릴 수 있습니다. 요청·읽기·정리를 함께 설계해야 합니다. 복습: 1~2절.

## Q3 — 객체별 계약과 프로세스 경계, 2점

client와 Session·Resource는 동시 사용 보장이 다르다는 설명 1점. client를 프로세스 사이에 공유하면 네트워킹 상태가 잘못 공유될 수 있고 metadata 수정·custom hook에도 주의해야 한다는 설명 1점. 복습: 4절.

## Q4 — 반드시 중단되지 않는다, 2점

코루틴의 대기 취소와 이미 실행 중인 스레드 함수의 종료는 다르다는 설명 1점. SDK timeout·작업 완료·업로드 상태·중복 재시도 정책을 확인한다는 대응 1점. 복습: 5절.

## Q5 — 수명과 자원 경계, 4점

요청뿐 아니라 본문 읽기도 블로킹 여부를 따져 오프로딩하거나 비동기 스트리밍을 사용합니다. 전체 객체를 동시에 메모리에 올리지 않도록 크기·chunk·동시 스트림을 제한합니다. 소비 중 오류·클라이언트 취소·종료에서 본문과 연결을 정리합니다. SDK timeout·재시도·전체 deadline을 맞추고 실제 큰 입력에서 메모리·루프 lag·풀 점유·오류를 검증합니다.

채점: 전체 블로킹 범위 1점, 메모리·동시성 1점, 취소·정리 1점, timeout·실측 1점. 복습: 2~5절.
