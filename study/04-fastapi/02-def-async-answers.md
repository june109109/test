# 4-2. 정답과 해설

[본문](02-def-async.md)

## Q1 — 아니다, 1점

직접 호출한 일반 helper는 현재 호출 스레드에서 실행됩니다. 프레임워크가 호출하는 경로 함수·Depends의 경계와 다릅니다. 복습: 1절.

## Q2 — 아니다, 1점

해당 AnyIO limiter가 제어하는 동기 작업 토큰과 프로세스 전체 스레드 수는 다릅니다. 다른 executor·네이티브 라이브러리·직접 만든 스레드 등이 있을 수 있습니다. 복습: 4절.

## Q3 — 루프 보호와 풀 비용, 2점

동기 경로를 스레드에서 실행해 루프의 직접 블로킹을 피하는 이익 1점. 스레드 한도·획득 대기·메모리·SDK 동시 사용·취소 등 비용 하나 이상 1점. CPU 병렬 가속이 자동으로 되는 것은 아닙니다. 복습: 3절.

## Q4 — 실행 경계와 운영 경계 구분, 2점

확인: 경로/의존성/helper의 스레드 위치, handler 대기 겹침, 응답 성공. 미확인: TCP·TLS·Uvicorn 처리, 멀티워커·LB 분산, 실제 S3·DB 지연, 운영 부하. 두 범주에서 각각 두 가지를 설명하면 1점씩입니다. 복습: 5~6절.

## Q5 — 호출 위치를 추적하고 실측, 4점

경로→의존성→helper→SDK에서 누가 어디에서 기다리는지 확인합니다. 동기 경로로 전환, 명시적 스레드 오프로딩, 비동기 SDK 중 실제 호출 사슬에 맞게 비교합니다. AnyIO·SDK 연결·하류·워커의 한도를 맞추고 timeout·취소 한계를 설계합니다. 루프 lag, 스레드 대기, 동시 요청 지연·오류·응답 내용을 검증합니다.

채점: 실행 경계 진단 1점, 대안과 비용 1점, 자원·timeout·취소 1점, 실제 비교 지표 1점. 복습: 1~6절.
