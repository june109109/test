# 4-7. 정답과 해설

[본문](07-lifecycle.md)

## Q1 — 아니다, 1점

일반적으로 워커 프로세스마다 앱과 lifespan이 실행됩니다. 자원·연결 예산과 중복 실행 가능한 작업인지 확인해야 합니다. 복습: 1~2절.

## Q2 — 보장되지 않는다, 1점

강제 종료·호스트 장애에서는 정리 코드가 실행되지 않을 수 있습니다. 정확성·복구를 finally에만 맡기면 안 됩니다. 복습: 4절.

## Q3 — 프로세스별 초기화, 2점

네트워크 client의 상태·소켓 공유가 응답 순서·안전성 문제를 만들 수 있고 공식 보장 밖이라는 설명 1점. 각 워커의 시작 수명에서 적절히 생성하고 종료하며 풀 예산을 곱해 관리한다는 수정 1점. 복습: 3절.

## Q4 — 중복·경쟁·준비 실패, 2점

동일 migration의 동시 실행·락 경합, 일부 성공/실패로 스키마 상태 불일치, 느린 초기화로 워커 준비 지연 등의 원인 두 개에 각 1점입니다. 별도 배포 단계·직렬화된 담당 작업·안전한 migration 도구가 필요할 수 있습니다. 복습: 적용 과제.

## Q5 — 수명과 업무 복구의 분리, 4점

워커마다 client·DB 풀을 만들고 준비 실패 시 해당 워커를 준비 완료로 알리지 않습니다. 요청마다 스트림·트랜잭션을 소유하고 완료·오류·취소에서 정리합니다. 종료는 신규 요청 차단과 제한된 drain 뒤 자원 정리로 진행합니다. 강제 종료 후에도 DB 트랜잭션과 외부 부작용을 확인할 수 있도록 작업 ID·멱등성·재처리 정책을 둡니다.

채점: 워커/요청 소유 1점, 준비 실패 1점, 정상 종료 경계 1점, 강제 종료 복구 1점. 복습: 1~5절.
