# 4-4. 정답과 해설

[본문](04-localstack.md)

## Q1 — 안 된다, 1점

SDK 호출 직전에 코드로 추가한 동기 대기입니다. 에뮬레이터·AWS 고유 지연이나 네트워크 조작 결과와 구분해야 합니다. 복습: 5절.

## Q2 — 아니다, 1점

실제 준비·쓰기·읽기·본문 검증이 필요합니다. 서비스 상태와 특정 API 기능 성공은 다릅니다. 복습: 3~4절.

## Q3 — 실행 경계와 효과 크기 구분, 2점

직접 동기 호출이 루프 스레드에서 진행되는 사실에 1점. 짧은 로컬 I/O에서는 영향이 작아 보여도 긴 I/O·다른 부하에서 달라진다는 설명에 1점입니다. 큰 성능 차이가 없다는 것과 실행 위치가 안전하다는 것은 같지 않습니다. 복습: 6절.

## Q4 — 확인 범위를 지키기, 2점

검증: 실제 로컬 S3 객체 바이트, API 응답, 실행 스레드, 실습 자원 정리. 미검증: 실제 AWS IAM·TLS·운영망·한도·모든 오류, Uvicorn/LB 멀티워커. 각 범주 두 항목에 1점씩입니다. 복습: 1·5·6절.

## Q5 — 희귀한 긴 호출까지 설계, 4점

루프에서 직접 SDK·본문 읽기를 하지 않도록 적절히 오프로딩하거나 비동기 SDK를 검토합니다. 긴 요청이 스레드·연결을 점유하는 동안 유입·대기열을 제한합니다. SDK connect/read·재시도와 전체 deadline, 취소 후 잔여 작업을 설계합니다. 루프 lag·풀 대기·꼬리 지연·오류를 보고 허용된 실제 환경에서 권한·네트워크·큰 객체·느린 응답을 검증합니다.

채점: 전체 블로킹 범위 1점, 점유·과부하 1점, timeout·취소·재시도 1점, 실제 환경 검증 1점. 복습: 6절과 4-3.
