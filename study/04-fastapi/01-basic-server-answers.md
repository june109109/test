# 4-1. 정답과 해설

[본문](01-basic-server.md)

## Q1 — 아니다, 1점

CPU를 양보해도 해당 서버의 처리 루프가 현재 handler를 기다리고 있으면 다음 handler는 진행되지 않습니다. OS가 다른 일을 할 수 있다는 것과 이 앱이 다음 요청을 처리하는 것은 다릅니다. 복습: 1·5절.

## Q2 — 아니다, 1점

실행 워커와 제출 대기열의 한도는 별개입니다. 이 executor의 제출 큐는 무제한이므로 유한한 학습 요청에만 사용합니다. 복습: 1·3절.

## Q3 — 실행 위치와 일반 성능 구분, 2점

하나의 프로세스 안 여러 스레드가 응답 처리에 참여했다는 설명 1점. CPU 병렬 가속·운영 확장성·균등 분배까지 입증한 것은 아니라는 설명 1점. 복습: 4~5절.

## Q4 — 처리 모델의 비교를 분리, 2점

유휴 지속 연결이 단일 handler를 붙잡는 영향을 제외했다는 설명 1점. 연결 재사용·TLS·풀·장기 접속의 효과는 비교하지 않았다는 설명 1점. 복습: 2절.

## Q5 — 실행 제한 이외의 경계, 4점

대기열과 전체 열린 연결 수를 제한하고 초과 유입은 명확한 정책으로 거절·지연시킵니다. 읽기·처리·전체 deadline을 구분합니다. 요청 크기와 느린 클라이언트 영향을 통제하고, 큐 대기·활성 워커·오류·지연을 관측합니다. 종료 시 신규 수락을 멈추고 진행 중 요청의 제한된 drain·취소·정리를 수행합니다.

채점: 큐·연결 한도 1점, timeout·크기 1점, 과부하·지표 1점, 종료·정리 1점. 워커만 1,000개로 늘리는 답은 하류·메모리 비용을 설명하지 못합니다.
