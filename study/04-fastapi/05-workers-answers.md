# 4-5. 정답·해설

[본문](05-workers.md) · [목차](../README.md)

## Q1 — 1점

아닙니다. 이미 수락한 지속 연결은 같은 워커가 처리할 수 있습니다. 새 연결 여러 개와 PID별 분포도 확인해야 합니다. 같은 연결과 같은 사용자는 별개입니다.

## Q2 — 1점

공유되지 않습니다. 각 프로세스의 주소 공간에 별도로 존재합니다. Redis 같은 외부 공유 저장소를 사용하더라도 자동 캐시 무효화까지 생기는 것은 아닙니다.

## Q3 — 2점

2 × 3 × (8 + 2) = 60입니다. 식과 값 1점, 배치·관리·배포 공존 연결이 별도임을 설명하면 1점입니다. 풀이 처음부터 60개를 모두 열었다는 뜻은 아닙니다.

## Q4 — 2점

CPU quota라는 전체 계산 예산은 늘지 않습니다(1점). 스케줄링·컨텍스트 전환·프로세스별 메모리 비용 등이 증가할 수 있습니다(1점). I/O 대기 비율이 큰 서비스는 CPU 전용 작업과 다른 양상을 보입니다.

## Q5 — 4점

각 1점: ① CPU 포화와 루프 블로킹을 구분한다. ② 스레드풀·DB/HTTP 풀·하류 지연을 확인한다. ③ 동일한 부하·데이터·자원 제한에서 워커 수만 바꾸며 반복 측정한다. ④ 처리량과 p95/p99·오류율·RSS·전체 DB 연결 예산을 함께 비교한다.

DB가 이미 포화되어 있다면 워커 증가가 연결 경쟁과 지연을 악화시킬 수 있습니다. 단순히 워커가 많다는 이유로 병렬 처리량이 보장되지 않습니다.

8점 미만이면 본문의 연결 분산과 설계 계산을 다시 읽고, ‘요청 수·연결 수·프로세스 수’가 다른 예를 하나씩 적으세요.
